# The project profile directory

Everything author- and register-specific lives in the user's own writing project,
not in this repo. This file is the schema.

**It is documented here, and owned by nobody.** `prose-tell-scan` writes it
(`init.mjs` scaffolds it, `ingest.mjs` and `calibrate.mjs` extend it) and reads
part of it; the `prose-review` bundle reads a different part. Neither owns
it, and neither may assume the other is installed.

That matters because **no manifest schema in this repo has a `dependencies`
field** — not `.claude-plugin`, not `.cursor-plugin`, not `.codex-plugin`, not
`.plugin`. There is no way for one bundle to declare it needs another. So this
document is the entire composition seam between them, and the rule that follows
is: *every consumer degrades gracefully when a file it wants is absent, and says
so out loud rather than guessing.*

## Layout

`init.mjs --project <dir>` produces exactly this:

```
<project>/.claude/humanizer.json                    path rules + defaults
<project>/.claude/humanizer/profiles/<register>/
    profile.json                inheritance, medium, rationale
    thresholds.json             hand-written fallbacks
    thresholds.derived.json     GENERATED by calibrate.mjs — the real ones
    allow.txt                   terms invisible to the scanner at any density
    voice.md                    the voice card
    corpus/human/               samples that drive calibration
    corpus/ai/                  negatives, for acceptance testing
```

Shipped registers are `essay`, `technical`, `narration`, `correspondence`.
`_base` is **not** scaffolded into the project — it stays in the bundle and is
inherited, so a bundle-side catalog fix reaches every project without a merge.

## Who reads what

| File | `prose-tell-scan` | `prose-review` |
|---|---|---|
| `humanizer.json` | resolves which register governs a file | same resolution, same order |
| `thresholds*.json` | the bands it flags against | — |
| `allow.txt` | suppresses matches | — |
| `catalog.json` (bundle `_base`) | the patterns | `prose-pattern-critic` reads it to know what is *already* covered deterministically; the reviser may read it as **diagnostic input, never as a target** |
| `corpus/human/` | `calibrate.mjs` derives bands | `prose-voice-critic` greps it for how this author actually writes |
| `voice.md` | **never read** | `prose-voice-critic`'s target |
| `profile.json` → `medium` | reported, not acted on | `prose-medium-critic` spawns only if this is set |

`voice.md` sitting unread inside the scanner's own skill directory is
deliberate. It exists so that "make this sound human" cannot collapse into
"sound like a generic competent human" — which is its own fingerprint. The
scanner cannot use it and must not pretend to.

**The catalog line is the one to get right.** A reviser is allowed to know that
a section leaned on the same construction four times; that is a useful fact
about a draft. What it must not do is treat catalog hits as the quantity to
minimise. Prose optimised against a tell list scores zero and reads like nobody
wrote it, which is the failure the catalog exists to *detect*, reproduced by the
tool meant to fix it. The reviser's target is `voice.md` and the corpus. The
catalog is a symptom list, not a fitness function.

## The corpus has two readers, and will have three

`corpus/human/` is the asset, and what makes it one is that the same samples
answer different questions:

| Reader | Consumes it as | Question |
|---|---|---|
| `calibrate.mjs` | percentile bands | what does this author's rhythm measure out to? |
| `prose-voice-critic` | reference text | does this draft sound like them? |
| a future drafter (`kind: author`) | exemplars | write something that sounds like them |

That third reader does not exist yet and is the point of the whole arrangement
for most people: drafting *from* a corpus rather than only auditing against it.
Nothing extra is needed on disk when it arrives — same directory, same
provenance requirement, same register split.

One ordering constraint follows, and it is worth stating before someone hits it:
**a drafter checked against uncalibrated bands is checked against this repo's
guesses**, not against the author. Corpus, then calibration, then generation.
Otherwise "sounds like me" quietly resolves to "sounds like the fallback".

## Resolution order

Per **file**, not per session, because one session touches an essay and a
reference doc. First match wins, and the report always names the rule that
fired:

1. `--profile <name>`
2. `profile: <name>` in the document's own frontmatter
3. a glob in `humanizer.json` → `profiles`
4. `default` in the same file
5. `_base`, with a warning that nothing matched

Profile *directories* are searched project-first:

```
--profiles-dir <dir>
<project>/.claude/humanizer/profiles/
<bundle>/skills/tell-scan/profiles/        ← shipped defaults
```

So keeping a local `essay` does not cost you the shipped `technical`.

## Degradation, stated per consumer

- **No `humanizer.json`** → no path rules. Everything else still works; the
  scanner falls back to `_base` and says it fell back.
- **No project profile directory** → the shipped profiles are used. The
  UNCALIBRATED banner prints on every run, which is the correct outcome, not a
  bug to quieten.
- **No `voice.md`, or an empty one** → `prose-voice-critic` may flag internal
  inconsistency but must not claim deviation from *your* voice, and must say
  which of the two it is doing. An invented voice card is worse than none,
  because it gives the critic a target that isn't you.
- **`prose-tell-scan` not installed** → `prose-review` runs its critics and
  states in the report that no deterministic scan backed them. It does not
  estimate the counts itself. A model auditing its own frequency tics finds the
  ones it remembers writing, not the ones it repeated.

## Provenance is a schema requirement, not a convention

Every file under `corpus/human/` needs frontmatter `source`, `date`, and
`human_authored: true`. Samples without it are excluded from calibration and
listed by name.

This guards the failure mode that kills a calibrated scanner slowly: AI-assisted
drafts leaking into the human corpus. Thresholds drift toward AI norms, the
scanner goes progressively blind, and **nothing in the output announces it is
happening** — the numbers still look like numbers. Add corpus material in its own
deliberate commit.

## Open: the directory name

The path is `.claude/humanizer/` for historical reasons — this bundle was called
`writing-humanizer` before the split. The name is wrong twice over: it names a
job neither bundle does, and it names one bundle for a directory both share.

It is unchanged so far because renaming it is a migration for anyone who has
already run `init.mjs`, and that is a separate decision from the bundle rename.
If it changes, `init.mjs` gains a migration path and this section becomes the
record of it.
